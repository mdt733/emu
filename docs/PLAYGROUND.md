# EMU Playground — static browser demonstration

**[▶ Try the public EMU Playground](https://mdt733.github.io/emu/)**

The public page loads a published 60M-step actor and runs MuJoCo/WASM and neural inference entirely in the browser. No server-side training, JAX or CUDA is required. It is a demonstration, **not independent held-out proof of reliability**.

The **View** button cycles: **orbit** (follow and inspect gait), **POV** (rigid chassis-mounted view with shake), and **level POV** (viewer-only horizon levelling and rotation smoothing). The telemetry distinguishes **robot lean** (feet midpoint to chassis-centre line) from **chassis pitch** (rigid torso/IMU angle). [Terminology](architecture.md#robot-lean-vs-chassis-pitch).

Settings → **Physical 1° ramp course (experimental)** inserts a real up/flat/down MuJoCo collision course and resets the simulation. The GPU trainer continues to use its fast flat-plane, rotated-gravity slope approximation, while the browser gets a small physical world. Transitions are not guaranteed within the 60M champion's learned capabilities. Switching the terrain changes no policy weights or training checkpoints.

## Preview before the champion exists

1. Install Node 24 and commit the actual `viewer/package-lock.json` generated by the successfully tested viewer build. It must match `viewer/package.json`; commit this *same lockfile*, not a hand-authored substitute.
2. Run in WSL:

   ```bash
   cd ~/robot_lab/emu
   source .venv/bin/activate
   python scripts/prepare_showcase.py
   cd viewer
   npm ci
   npm test
   npm run build
   npm run preview -- --host 127.0.0.1
   ```

3. Open the Vite preview URL shown in the terminal. The page must say **UNTRAINED PREVIEW** and must load automatically without drag/drop. The Settings button opens a separate right-hand drawer containing advanced commands and demo controls; joysticks remain unobscured while closed.
4. Verify actual rendering, WebAssembly loading, policy loading, mouse/touch controls and browser console in Chrome/Edge. The 10-cm grid, 1-m heavy lines, softly lit robot, world-origin X/Y axes and bounded motion trail should be visible. Their grid/trail/shadow toggles are in Settings; the scale legend hides on narrow phones to protect joystick space. The default `demo_zero` policy is not expected to walk.
5. To watch **live training checkpoints**, use `emu viewer --live --no-open` in a separate terminal and open **port 8765**, not the static preview on port 4173. Generated `viewer/public/` files are Git-ignored and may remain: the Python viewer serves its actual API independently of the Vite preview.

## Publish through GitHub Pages

The workflow `.github/workflows/emu-playground.yml` builds using `npm ci`, runs the JavaScript contract tests, verifies the static policy and WASM assets, and uploads `viewer/dist`. **Verify that the workflow trigger is `main`**. In GitHub repository **Settings → Pages → Source**, choose **GitHub Actions**. The workflow can be manually dispatched, or runs when relevant files are pushed to `main`. GitHub Pages needs the repository and Actions/Pages permissions configured for the account and repository.

The resulting URL will normally be `https://ACCOUNT.github.io/REPOSITORY/` (verify the actual link in GitHub Pages settings). The Vite build deliberately uses `base: './'` and the manifest uses relative paths so it works at a project subpath (or another static host). Do **not** run `emu viewer --live` on a public server; it is loopback-only and not authenticated.

## After the 400M run

Use your held-out evaluation panel to choose the **champion** (which might not be the chronologically final checkpoint), then export it:

```bash
cd ~/robot_lab/emu
source .venv/bin/activate
emu export-policy /ABSOLUTE/PATH/TO/SELECTED/checkpoints/final.pkl showcase/champion.emupolicy
python scripts/prepare_showcase.py --require-champion
cd viewer && npm ci && npm test && npm run build && npm run preview
```

Replace the example checkpoint path with the actual winner. `final.pkl` is merely an example, not a guessed location. This browser export contains only actor weights, normalizer and environment contract, not the PPO optimizer/critic. Review it before publishing; the actor and robot XML become public.

On success, from repository root:

```bash
git add .github/workflows/emu-playground.yml docs/PLAYGROUND.md scripts/prepare_showcase.py scripts/verify_showcase_dist.py viewer showcase
# After reviewing staged files and confirming there are NO .pkl, node_modules, build artefacts or secrets:
git diff --cached --check
git diff --cached --stat
# Commit and push to the branch that triggers Pages
```

The workflow automatically switches from **UNTRAINED PREVIEW** to **CHAMPION POLICY** if `showcase/champion.emupolicy` exists. No code change is required at that point. Site visitors can still drag another `.emupolicy` into the viewer; the published model does not alter private live training or PPO.

## What this does not guarantee

A static browser viewer is not an exact substitute for GPU/MJX held-out evaluation. Browser device performance varies, sensor-noise settings and resets differ, and random commands are not certified-safe. Test on at least one desktop and one mobile browser before treating it as production-ready.

## Viewer environment appearance (lightweight by design)

- The plane renders a cached 512×512 texture: fine lines every **0.10 m**, stronger lines every **1 m**, subtler half-metre lines. Texture UVs align with the world, not the robot. The render-only ground tile snaps by whole metres as EMU walks, leaving the *physical* MuJoCo ground unchanged.
- A small static X (warm) / Y (cyan) reference at the original spawn point and a capped 180-point movement trail help illustrate path and heading. The trail clears on every episode reset.
- A one-time gradient sky texture and distance fog give depth without external assets. Lighting uses hemisphere + fill + one warm shadow light. Its shadow map is **1024×1024**, down from the prior 2048×2048. No HDR probes, reflections or post-processing passes.
- Floor grid, trail and shadows can each be disabled in the settings drawer on slower mobile GPUs. None of these visual changes alter MuJoCo contacts, PPO observations, reward functions, policy inference or the training curriculum.

For a clean new clone or another device, follow the repo setup instructions and build the viewer; do not commit `viewer/dist/`, `node_modules/`, or generated `viewer/public/`.

### Troubleshooting: `Unexpected token '<'`

Vite's history fallback can answer a missing API or manifest path with `index.html`
(HTTP 200, `text/html`). The viewer checks MIME types instead of attempting to
parse it as JSON. If the site reports that `showcase.json` is missing, rebuild:

```bash
python scripts/prepare_showcase.py
emu viewer-build
python scripts/verify_showcase_dist.py
```

Then restart `npm run preview` in `viewer/` and hard-refresh the browser.
The local Python `emu viewer --live` keeps using its real JSON API.
